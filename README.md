## 製品概要 

### 背景(製品開発のきっかけ、課題等）
受験期の子供を持つ親は、子供に勉強へ集中してほしいと考えています。一方、子供自身も勉強に集中したいと思っていても、スマートフォンを自分の意志で手放すことが難しく、なかなか勉強に取り組めないという課題があります。
また、スマホに制限をかけたいけど、勉強用のアプリもあるので制限をかけられないという親もいます。
そこで私たちは、テストや受験日に向けて、スマートフォンの利用可能時間を段階的に減らしていくアプリ「Slope」を開発しました。


### 製品説明（具体的な製品の説明）
このアプリでは、親が利用時間の目標を設定し、登録されたテスト日程に合わせて利用上限が自動的に調整されます。また、テスト終了後には利用時間が一時的に回復する仕組みを取り入れることで、娯楽の時間を完全になくすことなく、次のテストに向けて再び少しずつ利用時間を減らしていきます。
さらに、親は子供の利用状況を確認でき、子供自身も利用割合を確認することで、スマートフォンの使いすぎを意識できるようにしています。
スマートフォンを急に使えなくするのではなく、無理のないペースで利用時間を減らすことで、親子双方のストレスを軽減しながら、子供が自然と受験勉強に取り組みやすい環境をつくることを目指しています。


### 特長
#### 1. テスト日と目標を登録すると、利用上限が日ごとに自動で下がります。
保護者は、計画の開始日、開始時の利用時間、最終目標、通常上限、利用可能時間帯を設定できます。テスト日が近づくほど上限が少しずつ下がり、テストが終わると一度回復します。日々設定を変更する手間を減らしながら、無理のないペースで利用時間を調整できます。

### 解決出来ること
* **各テストに合わせて利用可能時間を減らしていくことで、テスト前についスマホをいじってしまってもすぐに利用上限に達し勉強へと移行させられる
* **テストに合わせて利用時間を減らすために、保護者が毎回設定を調整する手間を省く
* **スマホの利用状況を、子どもには割合で伝えることで利用上限減少による心理的負担を軽減、保護者には具体的な時間で知らせることで「子供がスマホばかり触っていないか」という不安を解消
* **利用上限に達しても端末の利用が続き、勉強へ切り替えにくいこと
* **急にスマホを取り上げることで生じる親子の負担
### 今後の展望
* **子供の自己管理能力育成を促す目標設定への参加機能
* **親子のポジティブなコミュニケーションを促進するフィードバック機能の作成
* **単なるスマホ制限アプリに留まらない、豊かな親子関係を築くきっかけとなるアプリへ
### 注力したこと（こだわり等）
* **子ども向けの画面は、子どもが「ちょうど面白い」と感じて、自分から入れておきたくなるデザインにしました。** 制限のアプリは子どもに嫌がられて消されがちなので、使い続けたくなる見た目と楽しさを大事にしています。
* **保護者向けの画面は、シンプルにしながら操作のしやすさを最優先にしました。** 忙しい保護者が迷わず短い時間で設定や確認ができることが一番求められていると考え、その需要に合わせて設計しています。

## 開発技術

保護者用と子ども用は1つのアプリで、ログインした人の役割で画面が変わります。アプリは HTTP（JSON）でサーバと話し、サーバが DB に保存します。

```
保護者のスマホ ─┐
                ├─ HTTP（JSON）＋合言葉 ─→ サーバ（Hono / Vercel）─→ DB（Neon の PostgreSQL）
子どものスマホ ─┘                                  └─→ Google（ログインの確かめ）
  └ Kotlin の部品（使用時間・制限・ウィジェット）
```

くわしくは [docs/architecture.md](docs/architecture.md) を見てください。

### 活用した技術
#### API・データ
* **Google ログイン**（Google Identity）: サーバが ID トークンの署名・宛先・期限を確かめる（[jose](https://github.com/panva/jose)）
* **Android の使用状況へのアクセス**（UsageStats）: アプリごとの使用時間を取る
* **Android のユーザー補助**（AccessibilityService）: 上限のあと、決めた Web サイトを開いたらブラウザを戻す
* **Android の Device Owner**（DevicePolicyManager）: 子どもの端末から Slope を消せないようにする
* **PostgreSQL（[Neon](https://neon.tech/)）**: 本番・Preview の DB。手元とテストは [PGlite](https://pglite.dev/)（Node の中で動く Postgres）
* **[Vercel](https://vercel.com/)**: サーバの公開先（Production と Preview）

#### フレームワーク・ライブラリ・モジュール
* **アプリ**: React Native 0.88 ／ [Expo](https://expo.dev/) 58 ／ Expo Router ／ expo-dev-client ／ expo-camera と react-native-qrcode-svg（QR の読み取りと表示）／ AsyncStorage ／ @react-native-google-signin ／ react-native-svg
* **Android ネイティブ**: Kotlin の Expo Module（[modules/kit-native](modules/kit-native)）と config plugin（[plugins/](plugins)）
* **サーバ**: [Hono](https://hono.dev/)（API）／ [Zod](https://zod.dev/)（入力と出力の形の検査）／ jose（トークンの確かめ）
* **DB**: [Drizzle ORM](https://orm.drizzle.team/) と drizzle-kit（表の設計と migration）／ postgres ／ @neondatabase/serverless
* **開発の道具**: TypeScript 6 ／ [Vitest](https://vitest.dev/)（テスト約 1000 件）／ [Biome](https://biomejs.dev/)（lint と整形）／ tsx ／ Gradle と Android SDK

#### デバイス
* Android スマートフォン（targetSdk 36 = Android 16、minSdk 24）
* 動作確認: Galaxy A53（SC-53C、子ども役）・Galaxy SCG13（保護者役）・Android Emulator（Android 16）

### 独自技術
#### ハッカソンで開発した独自機能・技術
* **テスト日程に合わせて上限を少しずつ下げる計算**（C10）: 通常上限と目標から、テストの日に向けて日ごとの上限を決める（[src/server/plan/daily-limits.ts](src/server/plan/daily-limits.ts)）
* **子どもの端末の見張りと案内**（C2・C4）: 使用時間を取り、上限を超えたら案内の画面を出す。Web サイトの制限も行う（[modules/kit-native](modules/kit-native) の `MonitorService`・`LimitPrompt`・`WebGuardService`）
* **ホーム画面のウィジェット**（C5）: 今日の残り時間をいつでも見られる（`SlopeWidget`）
* **QR での親子の紐づけ**: QR は10分で切れ、1回だけ使える。番号をまちがえる回数に上限がある（[src/server/auth.ts](src/server/auth.ts)）
* **通信の約束を1か所に**: アプリとサーバで同じ Zod の定義（[contracts/](contracts)）を使い、入力と出力の両方を確かめる
* **セキュリティの自己点検**: 調べる役・直す役・確かめる役に分けて点検し、見つけた4件を直した（[PR #54](https://github.com/jphacks/sp_2602/pull/54)）
  * Google のトークンはサーバで署名を確かめる。合言葉は長い乱数で、DB にはハッシュだけを残す（30日使わないと無効・ログアウトでも無効）
  * どの API も、呼んだ人がその子どもを扱えるかを確かめる（[src/server/route.ts](src/server/route.ts) の `checkChildAccess`）
  * 今回直したもの: テスト用の合言葉を本番で断る・利用記録が溜まらないようにする・Android のバックアップを切る・release 版を自分の鍵で署名する
  * そのあとのセキュリティテストで直したもの（F-1〜F-7。[SECURITY_TEST/fixes.md](SECURITY_TEST/fixes.md)）: 合言葉を Android Keystore の鍵で封をして置く・日付と入力の形を制限する・DB の障害は 503 にする・ログに入力を出さない・連携を外したら前の家庭のデータを消して記録を残す・ログインと QR の発行に回数の上限
  * 保護者から子どもとの連携を外せるようにした（外された子どもの端末は約1分で制限が止まる）。子どもが自分でログアウトして制限を止める道はなくした
