# 最初の準備（このPCで初めて使うとき）

**AI は、このリポジトリで最初の作業をする前に、この手順を上から実行して確かめる。** 人間も同じ手順。
`npm run now` の「やること」の先頭に「このPCの準備がまだ」と出たときも、ここに戻る。

## 0. 人間に先にやってもらうこと（AI にはできない）
| やること | 確かめ方 | なぜ人間か |
|---|---|---|
| Node.js 24 を入れる | `node -v` が `v24.` で始まる | PC へのインストール |
| Git と GitHub CLI（gh）を入れる | `git --version` / `gh --version` | 同上 |
| GitHub の招待を承認する | リポジトリのページが開ける | 招待メールのボタン、または `https://github.com/<持ち主>/<リポジトリ>/invitations` |
| gh で、招待されたアカウントにログイン | `gh api user --jq .login` が自分の GitHub 名 | ブラウザでのログインが要る（`gh auth login`） |
| 自分の役（id）を AI に伝える | — | lead / back-a / front-a / front-b のどれか。AI は推測で決めない |

非公開のリポジトリは、招待を承認するまで「Repository not found（見つからない）」になる。別の GitHub アカウントでログインしていても同じになる。

## 1. 取ってくる（まだなら）
```
git clone https://github.com/<持ち主>/<リポジトリ>.git
cd <リポジトリ>
```
以降はすべて**リポジトリの一番上のフォルダで**実行する（hook がそこからの位置で動くため）。

## 2. 準備をまとめて実行する
```
npm run kit:setup -- <自分のid>
```
1つのコマンドで、上から順に次を行い、それぞれに ✓ / ✗ を出す。何度実行してもよい（済んでいるものは飛ばす）。

| 順 | 何をするか | ふつうの言葉で |
|---|---|---|
| 1 | Node のバージョンを確かめる | 決めた版の Node か |
| 2 | `npm ci` | 必要な部品（依存パッケージ）を、決めた版のとおりに入れる。**これをしないと他が全部動かない** |
| 3 | git hooks を有効にする | コミットの前に自動で検査が走るようにする |
| 4 | 自分の id を記録する | このPCで作業するのは誰か（`.kit-member`。GitHub には上がらない） |
| 5 | `.env` を作る（なければ） | 手元用の設定ファイル。`MOCK=1` なので AI のキーなしで開発できる。すでにあれば触らない |
| 6 | gh で GitHub を使えるか | Issue・PR を作れるか。ログインしているアカウントが自分か |
| 7 | `git fetch` | GitHub の最新の状態を取ってくる（自分のファイルは変えない） |
| 8 | `npm run doctor` | 最終確認。型チェックと、試しにアプリを起動して応答するかまで見る（1〜2分） |

最後に **「✓ 準備完了」** と出れば終わり。

## 3. 確かめる（AI は結果を人間に報告する）
```
npm run now
```
「やること」に準備の行が出なければよい。報告は次の形:
```
準備: 完了 / 未完了
自分: <id>（<役割>）
kit:setup: <✓ の数> / <全体の数>（✗ があればその行と → の内容）
人間にお願いしたいこと: <なければ なし>
次: npm run now の「やること」の1つ目
```

## 4. 人間が別のターミナルで（AI は実行しない）
- `npm run kit:alarm -- --test` で通知が出るか確かめる。当日は `npm run kit:alarm` を動かしっぱなしにする（締め切りを知らせる見張り役）。
- Codex を使う人は docs/kit/codex.md の「最初に1回」（フォルダの trust・hook の確認・GH_TOKEN）。

## うまくいかないとき
| 出たもの | 原因 | 直し方 |
|---|---|---|
| `Repository not found`（clone のとき） | 招待をまだ承認していない／別のアカウントでログインしている | 0 の表の「招待」「gh でログイン」 |
| `Node 24 系 ✗` | Node の版が違う | Node 24 を入れる（人間）。nvm を使っているなら `nvm use` |
| `npm ci` で `EPERM` / `EBUSY` | 起動中の `npm run dev` や VS Code がファイルをつかんでいる | dev サーバを止めて、もう一度 `npm run kit:setup` |
| `npm ci` でネットワークのエラー | 回線・プロキシ | つながる回線で、もう一度 |
| `自分 = 未設定 ✗` | id を渡していない | 人間に役を聞いて `npm run kit:setup -- <id>` |
| `gh で GitHub を使える ✗` | ログインしていない／別アカウント | 人間が `gh auth login`。Codex の中なら docs/kit/codex.md の GH_TOKEN |
| `git fetch ✗`（Codex） | サンドボックスの中から `.git` に書けない | 「サンドボックスの外で実行してよいか」を承認する（docs/kit/codex.md） |
| doctor の `型チェック ✗` | main 以外のブランチにいて、途中の変更がある | `git switch main` → `git pull` してから、もう一度 |
| doctor の `/api/health ✗` | ポートの衝突・起動のエラー | `MOCK=1 npm run dev` を実行して、出たエラーを読む |
| 日本語が文字化けする | Windows PowerShell 5.1 | PowerShell 7（`pwsh`）を使う |

2回やり直しても同じ ✗ が出たら、止まって人間に、出た行をそのまま見せて相談する（AGENTS.md「2回失敗したら」）。
