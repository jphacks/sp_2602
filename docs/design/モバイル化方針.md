# キットのモバイル化方針（下書き）

作成日: 2026-10-16 / 状態: 決定済みの方針（作業の分け方は `tmp/issue/` の A〜E）

## 1. 目的
このハッカソン用キットを、Next.js の Web アプリ向けから **Android アプリ向け**に作り替える。iOS は将来対応とし、今回は作らない。
キットは **ペアレンタルコントロールアプリ専用**とする（汎用化はしない）。

## 2. 決定したこと

| 項目 | 決定 | 理由・補足 |
|---|---|---|
| Web 版 | **消す**（置き換え） | スタックの切り替え機構は作らない。Web に戻すときは git の履歴から取り出す。 |
| アプリの土台 | **React Native + Expo Development Build** | Kotlin のネイティブモジュールを足せる。Expo Go（Kotlin が動かない試用版）は使えない。 |
| 言語 | TypeScript（UI・共通処理）+ Kotlin（Android 固有の処理） | `tmp/docs/使用言語.md` の方針どおり。 |
| データベース | **Vercel 上の Neon（Postgres）** | 認証・アクセス制御・同期の付いたバックエンドサービスは使わない。 |
| 対象 OS | Android のみ（iOS は将来） | OS 固有の処理は共通処理から分けておく。 |
| キットの位置づけ | **ペアレンタルアプリ専用** | SelfLock・AccessibilityService など、お題固有の内容をキットに入れてよい。 |

## 3. 決定により変わること

### 3.1 バックエンドサービスを使わない影響
`使用言語.md` の初版は、認証・アクセス制御・同期の付いたバックエンドサービスを第一候補にしていたが、Neon は「データベースだけ」で、認証・アクセス制御・同期の仕組みは付いてこない。次を自分たちで用意する必要がある。

| 使用言語.md の初版の想定（バックエンドサービス） | Neon での代わり |
|---|---|
| 認証（親子アカウント） | 認証の仕組みを別に選ぶ（未決・5節） |
| RLS（行ごとのアクセス制御）で子どもの変更を禁止 | **API サーバ側で保護者かどうかを検証する** |
| Realtime（制限ルールの同期） | 定期同期、または Push 通知（未決） |

### 3.2 API サーバが必要になる
アプリ（端末）から Neon に直接つなぐと、接続情報が端末に入り危険。そのため、**Vercel 上に API サーバを置き、アプリはその API だけを呼ぶ**。
- Web 版は消すが、Vercel の API（Functions）は残る。
- `contracts/` の Zod の型を、アプリと API の両方が使う。これがキットの「型で繋がる」考え方の中心になる。
- 今の `src/server/`（`route.ts`・`analyze.ts`・`db/`）は、Next.js に依存しない形に作り直す。

### 3.3 専用にしたことで変わること
- 契約（`contracts/`）に、親子・制限ルール・使用状況の型を最初から入れられる。
- 設計原則（Android 固有の処理は Kotlin に分ける、制限処理は端末内で完結させる、保護者権限はサーバ側で検証する）を、キットの規則にできる。
- お題の中身は `docs/DEMO.md`・`docs/requirements/` に、技術構成は `docs/rules/stack.md` に置く（置き場を分ける）。

### 3.4 キットの各部分の扱い

| 区分 | 対象 | 方針 |
|---|---|---|
| 作り替える | `src/app`・`src/lib`・`next.config.ts`・`postcss.config.mjs` | Expo のアプリ構成に置き換える。 |
| 作り替える | `scripts/check-style.mjs`・`contracts/tokens.css` | Tailwind 前提。RN 用のスタイル規則に直す（NativeWind か StyleSheet は未決）。 |
| 作り替える | `scripts/shot.mjs` | ブラウザの撮影から、エミュレータ・実機の撮影（`adb`）へ。 |
| 作り替える | `scripts/doctor.mjs`・`setup.mjs` | JDK・Android Studio・`adb`・実機接続の確認を足す。 |
| 作り替える | `scripts/api.mjs`・`db-push.mjs`・`src/server/db` | Next.js 依存を外す。Neon + Drizzle は残す。 |
| 作り替える | `contracts/screens.md`・`kit:stub` | 画面名を RN の画面に合わせ、仮の画面生成を直す。 |
| 書き直す | `AGENTS.md`・`README.md`・`docs/rules/stack.md`・`docs/members/*`・`.github/CODEOWNERS`・`.github/workflows/ci.yml` | Web の記述を直す。**正本の `stack.md` を先に直す。** |
| そのまま | `now`・`step`・`declare`・`merge`・`issue`・`status`・`handoff`・`schedule` など | 言語に依存しない。 |

## 4. 進め方
1. この方針に合意する。
2. 専用ブランチ（例 `feat/mobile-stack`）を作る。`main` では作業しない。
3. 小さなまとまりごとにコミットする。順番は次のとおり。
   1. `docs/rules/stack.md`・`AGENTS.md`（正本を先に直す）
   2. `package.json`・アプリの雛形（Expo）・API の雛形
   3. `check`・`doctor`・`shot` などの道具
   4. `kit:reset`（キックオフで例を消す仕組み）の整合
4. 確認: `npm run check` と `kit:reset` が通ることを確かめる。
5. 作業は GitHub の issue に分けて登録する（登録前に確認を取る）。

## 5. 決定した技術選択と、キックオフで正式に決めること

### 5.1 書き換え前に決定（2026-10-16）
| 項目 | 決定 | 理由 |
|---|---|---|
| API サーバの書き方 | **Hono を Vercel Functions で動かす** | Next.js をやめても、`route.ts`・`handleStream` と同じ形で書ける。Zod の型を共有できる。 |
| RN のスタイルの規則 | **StyleSheet + `tokens.ts`（色・余白の名前だけを使う）** | 「名前だけ」の規則をスクリプトで検査できる。NativeWind は Development Build で設定が増える。 |
| パッケージ管理 | **npm のまま** | 変える理由がない。 |

### 5.2 お勧め案を採用（キックオフで正式に決める。キットには置き場だけ作る）
| 項目 | お勧め案 | 備考 |
|---|---|---|
| 認証の仕組み | 保護者はメールか Google でログイン。子ども端末は、保護者が発行するペアリングコードで紐づける | 契約には「役割（保護者・子ども）」の型の置き場だけ作る。 |
| 制限ルールの同期 | 定期同期（一定時間ごとに取りに行く）。最後に取ったルールは端末に保存し、オフラインでも適用する | Push 通知は Firebase の設定が要るので、後回し。 |
| 対応 Android バージョン | Android 16 のみ | 実機で確認する範囲を増やさない。 |
| アプリの配布方法 | APK の直接配布 | `AccessibilityService` を使うと Google Play の審査で注意が要る。公開は別の話。 |

## 6. 注意
- 候補のライブラリは `package.json` に先に入れず、使うと決まった時に PR で足す（「依存パッケージを勝手に足さない」ルールを維持する）。
- Android の制約として、強制停止やアンインストールを完全に防ぐことはできない（`使用言語.md` の6節のとおり、要件に含めない）。
