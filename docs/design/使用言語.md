
# Android向けペアレンタルコントロールアプリ

## 技術・開発言語要件定義（Ver. 1.0）

**策定日：2026年10月16日**
**ステータス：基本方針確定**

### 1. プロジェクト概要

保護者が子どものAndroidスマートフォンの利用時間を遠隔管理できる、ペアレンタルコントロールアプリを開発する。

アプリごとの使用時間を計測し、保護者が設定した制限時間を超えた場合に、対象アプリの使用を制限する。

既存のオープンソースプロジェクト「SelfLock」を参考に開発する。

### 2. 開発言語・フレームワーク

| 項目                  | 採用技術                              | 状態     |
| --------------------- | ------------------------------------- | -------- |
| メインフレームワーク  | **React Native**                | 確定     |
| メイン開発言語        | **TypeScript**                  | 確定     |
| Androidネイティブ開発 | **Kotlin**                      | 確定     |
| Android UI            | React Native                          | 確定     |
| Androidネイティブ連携 | Native Modules（Turbo Modulesを候補） | 方針確定 |
| iOSネイティブ開発     | Swift                                 | 将来対応 |

| バックエンドサービス  | Vercel 上の API サーバ（Hono）+ Neon（Postgres） | 確定 |
| ローカルデータベース  | Room（SQLite）                        | 採用候補 |
| 参考プロジェクト      | SelfLock                              | 確定     |

**基本方針：アプリのUIと共通ロジックはTypeScript、Android固有の制御はKotlinで実装する。**

### 3. 対応プラットフォーム

| 項目                   | 要件               |
| ---------------------- | ------------------ |
| 初期対応OS             | Android 16         |
| Android API Level      | 36                 |
| 保護者端末             | Android            |
| 子ども端末             | Android            |
| 将来対応OS             | iOS                |
| クロスプラットフォーム | React Nativeを利用 |
| Androidの初期化        | 不要               |
| PCによる初期設定       | 不要               |

Android 16を初期開発・検証対象とする。対応可能な最低Androidバージョンは今後決定する。

将来的なiOS対応を想定し、OS固有の処理を共通UI・ビジネスロジックから分離する。

### 4. アプリケーション構成

**保護者用と子ども用を1つのアプリケーションに統合する。**

初期設定で役割を選択し、アカウントの権限に応じて機能を切り替える。

| 保護者モード           | 子どもモード           |
| ---------------------- | ---------------------- |
| 子どもの端末管理       | 使用時間の計測         |
| アプリ別の時間制限設定 | 制限ルールの適用       |
| 利用状況の確認         | 制限超過時のブロック   |
| 制限時間の遠隔変更     | 保護者設定の受信       |
| 利用延長の承認（将来） | 利用延長の申請（将来） |

子どもがアプリ内の操作によって保護者権限を取得したり、制限設定を変更したりできないようにする。

### 5. Androidネイティブ機能

Kotlinで以下の機能を実装する。

| Android API・技術        | 用途                         |
| ------------------------ | ---------------------------- |
| `UsageStatsManager`    | アプリごとの使用時間取得     |
| `AccessibilityService` | 使用中アプリの検出           |
| `ForegroundService`    | バックグラウンド監視         |
| `AlarmManager`         | 時間指定の制限処理           |
| `BlockOverlayActivity` | 制限画面の表示               |
| `Room`                 | 利用履歴・制限ルールの保存   |
| `Coroutines`           | 非同期・バックグラウンド処理 |

監視・制限エンジンは、React NativeのUIが起動していなくても動作する独立したKotlinコンポーネントとして実装する。

ただし、Androidのバックグラウンド実行制限やユーザーによる強制停止を完全に回避できるものではない。

### 6. 端末管理・セキュリティ要件

採用する管理方式は、**SelfLock型のアプリケーション制限方式**とする。

| 項目                          | 方針                           |
| ----------------------------- | ------------------------------ |
| Device Owner                  | 使用しない                     |
| Device Admin                  | 必須としない                   |
| 端末初期化                    | 不要                           |
| アプリの使用制限              | AccessibilityService等を利用   |
| 制限設定の変更                | 保護者のみ許可                 |
| アプリ内の権限管理            | サーバー側で検証               |
| オフライン動作                | 最後に同期した制限ルールを適用 |
| アンインストールの完全防止    | 要件に含めない                 |
| Android設定からの権限解除防止 | 要件に含めない                 |

子どもが通常のアプリ操作だけで制限ルールを変更できないことを必須要件とする。

一方、OSの設定変更による監視停止やアンインストールを完全に防ぐことは要求しない。

### 7. バックエンド・データ管理

Vercel 上の API サーバ（Hono）と Neon（Postgres）を採用する。アプリは API だけを呼び、データベースには直接つながない。Neon はデータベースだけで認証・アクセス制御・同期の仕組みは付かないため、これらは API サーバ側で用意する（詳細は `モバイル化方針.md`）。

必要な機能は以下のとおり。

- 親子アカウントの認証・紐づけ
- 保護者による制限ルールの登録・変更
- 子ども端末への制限ルール同期
- アプリ使用状況の保存・取得
- サーバー側のアクセス権限管理
- オフライン時のローカル制限継続

API サーバが、リクエストした人が保護者かどうかを毎回検証し、子どもアカウントからの制限ルール変更を禁止する。

### 10. 開発時の設計原則

**① TypeScriptとKotlinの責務を分離する**

UI・共通ロジックはTypeScript、Android固有の監視・制限処理はKotlinに集約する。

**② 将来的なiOS対応を考慮する**

Android固有の実装を共通ロジックに直接組み込まない。将来的にSwiftによるiOS実装へ置き換えられるインターフェースを設計する。

**③ 制限処理をローカルで完結させる**

インターネット接続やReact NativeのUI稼働状態に依存せず、端末内で制限ルールを判定できる構成とする。

**④ 既存OSSを活用する**

SelfLockの実装を参考に、既存コードの再利用と必要な部分の新規実装を組み合わせる。

**⑤ 保護者権限をサーバー側で保証する**

フロントエンドでの表示制御だけに依存せず、バックエンドで設定変更権限を検証する。

## 11. 確定事項と未決定事項

### 確定事項

- React Native + TypeScriptを採用する。
- Androidネイティブ処理はKotlinで実装する。
- Android 16を初期開発対象とする。
- 保護者・子ども用アプリを統合する。
- SelfLockを参考実装として活用する。
- Device Ownerは採用しない。
- 端末初期化不要の方式とする。
- 保護者が遠隔で使用時間を設定できるようにする。
- 子どもがアプリ内で制限ルールを変更できないようにする。
- 将来的なiOS対応を考慮する。
- バックエンドは Vercel 上の Hono の API サーバ + Neon（Postgres）とする（2026-10-16）。
- React Native 環境は Expo Development Build、パッケージ管理は npm とする（2026-10-16）。

### 未決定事項

| 項目                  | 検討内容                                            |
| --------------------- | --------------------------------------------------- |
| 対応Androidバージョン | Android 16以外も対応するか                          |
| アカウント認証        | メール・Googleログインなど                          |
| データ同期            | Realtime / Push通知 / 定期同期                      |
| iOS対応時期           | Android版完成後に検討                               |
| アプリ配布方法        | Google Play / APK直接配布                           |

### 最終的な技術方針

**React Native（TypeScript）をアプリケーションの中心とし、KotlinでAndroidのスクリーンタイム制限エンジンを実装する。SelfLockを参考に、保護者による遠隔管理機能を追加する。**

この要件定義を、今後の設計・Codexによる開発の基準とします。
