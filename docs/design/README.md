# デザイン（front-a の所有）

- Figma: （URL を貼る）
- 試作（プロトタイプ）: （Figma の「共有 → プロトタイプのリンク」を貼る。全員がスマホで開いて押せるもの）
- 雰囲気: （一言。例: 白地に濃い紺、角は小さめ、文字は大きめ）

デザインは **画面の絵の前に「状態」** から作る。画面は「どの状態のときに、何が見えて、何を押すとどこへ行くか」の集まりで、それを先に決めると、契約（受け渡すデータ）・画面の作り込み・e2e の確認項目が全部そこから決まる。進め方は docs/members/front-a.md のステップ。

## Figma のファイルの整理（ページ分け）
1つのデザインファイルに、次のページを作る（名前もこのまま）。

| ページ | 置くもの | いつまで |
|---|---|---|
| `00 表紙` | このファイルの使い方（どのページを見ればよいか）、試作のリンク、凍結の状態（何時に何を凍結したか） | キックオフ |
| `01 フロー` | **状態遷移図**。状態ごとの小さなカード（状態名＋画面の縮小）を並べ、矢印にイベント名を書く（下の「状態遷移図の描き方」） | 11:20（契約凍結の前） |
| `02 線画` | 状態ごとの 375px のフレームを、色を付けずに四角と実際の文言だけで。プロトタイプの矢印をつないで**押して試せる**ようにする | 11:20 |
| `03 画面` | 作り込んだデザイン。状態ごとのフレーム（`02 線画` と同じ名前）。DEMO.md で見せる状態から作る | 第1統合まで（DEMO の分は同期点1まで） |
| `04 部品` | 共通部品（ボタン・入力欄・カードなど）をコンポーネントにし、状態をバリアントで持つ（通常 / 押せない / 読み込み中 / エラー） | 同期点1 |
| `05 トークン` | 色・文字・角丸・余白を **変数** で。名前は `contracts/tokens.css` と同じ（`bg` / `surface` / `text` / `muted` / `line` / `primary` / `danger` …） | 11:30（契約凍結） |
| `99 置き場` | 不採用の案・古い版（消さずにここへ移す） | — |

### 名前の決まり
- フレーム名は **`<画面id>/<状態id>`**（例 `result/loading`）。画面 id は `contracts/screens.md` の id、状態 id は下の状態の表の id。`02 線画` と `03 画面` で同じ名前にする（見比べやすく、AI にも「この状態の絵」と指せる）。
- スマホ幅 375px を先に作る。PC 幅は主要な画面だけ `<画面id>/<状態id>@pc`。
- 書き出し画像はこのフォルダに `<画面id>-<状態id>.png`（Figma の書き出し名もこれに合わせる）。

## 状態遷移図の描き方（`01 フロー`）
- **状態** = 利用者から見て画面の見え方が変わるところ。1つの画面に状態がいくつもある（例: 入力中・計算中・結果・エラー）。
- **イベント** = 状態が変わるきっかけ。次の4種類に分けて、矢印のラベルに書く:
  - 操作: 利用者が押す・入れる・切り替える（例「主ボタンを押す」）
  - 応答: サーバが返す（例「成功」「失敗」「時間切れ」）
  - 時間: 待つ・アニメーションが終わる（例「0.7秒後」）
  - 入口: URL を直接開く・戻る・再読み込み（例「/result を直接開く（データなし）」）
- 分かれ道には **条件** を書く（例「12月分が今年に入らない」）。条件に使う値は、契約（`contracts/schemas.ts`）に項目として必要になる。
- 最低限、各画面で次を考えて、無いなら「無い」と書く（screens.md の UX の約束から）:
  初めて開いた（空・例の数字入り）／入力の誤り／待ち（1秒を超えたら文字で知らせる）／成功／失敗（何が起きたか＋次に押すもの）／URL を直接開いた・データが無い
- 描き方は自由（Figma の線と矢印でよい）。FigJam で描くなら、そのリンクを `00 表紙` に貼る。

## 状態の表（ここが正。Figma と食い違ったらここを直してから Figma を直す）
| 画面 id | 状態 id | 状態 | 入るきっかけ（イベント） | 画面に出すもの（実際の文言） | 使う契約の項目 | 次の状態（イベント） | Figma フレーム | 書き出し画像 |
|---|---|---|---|---|---|---|---|---|
| （例）`home` | `input` | 入力中 | 入口: 開く | 見出し・入力欄・主ボタン「判定する」 | なし | `loading`（操作: 主ボタン） | `home/input` | `home-input.png` |
| （例）`home` | `loading` | 判定中 | 操作: 主ボタン | 「判定しています…」・ボタンは押せない | なし | `result/done`（応答: 成功）・`home/error`（応答: 失敗） | `home/loading` | `home-loading.png` |

- 1行 = 1つの状態。この行がそのまま、(1) Figma のフレーム (2) MOCK の固定データ（`contracts/fixtures.ts`）(3) e2e の確認項目（`tests/e2e/`）になる。
- 「画面に出すもの」は実際の文言で書く（「結果を表示」ではなく、利用者が読む一文）。特に、その画面で**利用者が一番知りたい答えの一文**があるかを確かめる。
