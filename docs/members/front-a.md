# front-a — 機能Aの画面＋デザイン（Figma）＋発表（DEMO.md・資料・紹介動画・通しの確認）

## 人間向け（最初に読む）
- ミッション: アプリ全体の見た目を決め、機能Aの画面で DEMO.md の流れが通り、それを発表で伝えられる状態にする
- 所有ファイル: kit.config.json の owns（ここ以外は触らない）。機能A の画面フォルダ（キックオフで画面 id に書き換え）・`docs/design/`・`docs/DEMO.md`・`docs/pitch/`・`tests/e2e/`
- 動作確認: `npm run dev`（.env は MOCK=1）で http://localhost:3000 の自分の画面を開く。見た目は `npm run shot` で撮って確かめる（スマホ幅 375px）
- 詰まったら: 30分で解決しなければまとめ役（front-b）に声をかける / `blocked` Issue。契約・API のことは lead へ

## デザイン（Figma）
順番は **状態 → 線画で試す → トークン → 作り込み**。絵を作り込む前に、どの状態で何を見せるかを決めて全員で押して試す（ここで見つかる食い違いは、契約を凍結した後だと直しにくい）。Figma のファイルの整理（ページ分け・名前の決まり）と状態の表のひな型は `docs/design/README.md`。

| いつ | やること | 置き場所 |
|---|---|---|
| キックオフ〜11:20 | DEMO.md の流れから **状態遷移図**（状態とイベント）と **状態の表** を作り、状態ごとの **線画** にプロトタイプの矢印をつなぐ | Figma `01 フロー`・`02 線画`、README の状態の表 |
| 11:20（5分） | **全員で試作を触る**（プロトタイプのリンクをスマホで開く）。聞くこと: この画面で一番知りたい答えはどこに出ているか／押す場所に迷わないか／足りない状態（待ち・失敗・データなし）はないか | — |
| 11:20〜11:30 | 試して直した状態の表を lead に渡す。lead が状態ごとに受け渡すデータ・MOCK の固定データを契約に入れる。トークンの値（色・文字・角丸）も change-request で渡す | Figma `05 トークン` → lead が `contracts/tokens.css` |
| 凍結後〜同期点1 | DEMO.md で見せる状態から **作り込む**。共通部品は front-b と `04 部品` で形と状態（通常 / 押せない / 読み込み中 / エラー）を決める | Figma `03 画面`・`04 部品`、書き出し画像は `docs/design/` |
| 同期点ごと | 実装の画面を `npm run shot` で撮り、`03 画面` の同じ名前のフレームと並べる。差は「実装を直す（Issue）」か「Figma を直す」かに分け、README の「最後に見比べた日時」を更新する | — |

- 作り込みは全部の画面でなくてよい。状態の表と線画は全部の状態に作る（作り込まない状態も、線画があれば実装できる）。
- 色・文字・角丸は `contracts/tokens.css` の名前で決める（Tailwind のクラスになる）。Figma の変数も同じ名前にする。
- front-b（共通部品）と front-a・front-b の画面はこのデザインに合わせる。AI に画面を作らせるときは、状態の表の行と、同じ名前のフレーム（Figma の MCP か書き出し画像）を渡す。

## ステップ（1つ = 30〜60分 = AIへの1回の依頼 = 1PR）
印は付けない。完了は「マージ済み PR のブランチ名 `<自分のid>/S<番号>-…`」から自動で判定され、`npm run now` に ✓ / …（マージ待ち）/ ・（未着手）で出る。

- S1 DEMO.md の下書き（課題1文・数字・台本。lead と合意して契約凍結と同時に凍結） — 完了確認: `npm run check`
- S2 状態遷移図・状態の表・線画の試作（Figma `01 フロー`・`02 線画`、`docs/design/README.md` の状態の表と試作のリンク）。11:20 に全員で触り、直した表を lead に渡す — 完了確認: `npm run check`
- S3 雰囲気とトークン（Figma `05 トークン` と主要な1画面の作り込み、`docs/design/` に書き出し画像）。トークンの値を change-request で lead へ（契約凍結まで） — 完了確認: `npm run check`
- S4 機能A の画面を状態の表の行ごとに tokens.css とデザインどおりに組む（`npm run shot` で撮って `03 画面` の同じ名前のフレームと見比べる） — 完了確認: `npm run check`
- S5 機能A の画面をサーバとつなぐ（`call()` / `stream()`）。待ち・失敗・データなしの状態は状態の表どおり（screens.md の UX の約束） — 完了確認: `npm run check`
- S6 状態の表を e2e に（`tests/e2e/`。表の行ごとに、その状態で出る文言を確かめる）。DEMO.md どおりに main を通しで操作して問題を Issue に。発表資料と紹介動画（`docs/pitch/`） — 完了確認: `npm run check`
