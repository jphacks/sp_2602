# Slope の説明書（目次）

**Slope（スロープ）** は、子どものスマホの使用時間を、テストに向けて**坂（スロープ）のように少しずつ下げていく**ための Android アプリです。
保護者が「計画（はじめの上限 → 最終目標）」を決め、親子どちらかがテストの日程を入れると、サーバが「その日の上限（分）」を毎日ぶん計算します。
子どものスマホは使った時間を測って「今日は何％使ったか」を出し、上限に届いたら案内を出します。保護者は子どもが使った時間（分）を週のグラフで見られます。

- 保護者の端末と子どもの端末は、**同じアプリ**を使います。ログインのあと、QR コードでつなぐと役割（保護者／子ども）が決まります。
- この説明書は **2026-10-17・ブランチ `feature/app-skeleton`・commit `3b588ce`** のコードを読んで書きました。コードと説明が違ったら**コードが正しい**ので、説明書を直してください。

## 言葉の表

| 言葉 | 意味 |
|---|---|
| C1〜C10 | 機能の番号（MVP_SPEC 4章・FigJam）。C1 ログインと QR の紐づけ、C2 使用時間の取得、C3 割合と到達の計算、C4 上限に届いたときの案内、C5 ウィジェット（MVP の後）、C6 親が見るグラフ、C7 設定の取得とキャッシュ、C8 利用記録の送信、C9 制限対象外アプリ、C10 日別上限の計算 |
| D1〜D8 | データの置き場の番号（MVP_SPEC 6章）。D1 利用者、D2 家族のつながり、D3 テスト日程、D4 使用時間、D6 日別上限、D7 制限対象外アプリ、D8 利用計画 |
| 子01・親01・共01 など | Figma の画面の番号（子＝子ども用、親＝保護者用、共＝両方）。一覧は [screens.md](screens.md) |
| Q1〜Q23 | 仕様の質問番号。承認済み事項は [decisions.md](decisions.md)、未承認・保留事項は [open-questions.md](open-questions.md) |
| 契約 | アプリとサーバの「この形で送ると、この形で返る」という約束。`contracts/` に型として書いてある |
| API | サーバの窓口。`/api/plan/save` のような道（path）で呼ぶ |
| 合言葉（セッション） | ログインするとサーバが出す文字列（token）。以後の API に付けて「誰が呼んだか」を示す |
| 役割（role） | `parent`（保護者）か `child`（子ども）。QR の紐づけが終わるまでは `null` |
| 通常上限 | テストや計画がない日の1日の上限（分）。紐づけの直後に保護者が決める |
| 計画（S・G） | 保護者が決める「計画の開始日・開始上限 S（分）・最終目標 G（分）」 |
| 日別上限 | その日の上限（分）。サーバが C10 で計算して日付ごとに持つ |
| 空白期間 | 夏休みなど、保護者が登録する「制限なし」の期間 |
| 版（configVersion） | 子ども1人の設定が変わるたびに 1 増える番号。古い設定と新しい設定を取り違えないために使う |
| スナップショット | ある時点の設定を丸ごと写した1組（C7 で端末が受け取る） |
| ポーリング | 端末が一定の間隔（ふつう30秒）でサーバに「変わった？」と聞きに行くこと。Push 通知は使っていない |
| MOCK | 本物の代わりの仮の動き。今のサーバはデータをメモリに持つ仮のサーバ（`MOCK=1` でデモの人とデータが入る） |
| 冪等（べきとう） | 同じものを何回送っても1回と同じ結果になること（利用記録の送り直しで二重にならない） |
| Context | React の「画面全体でデータを共有する仕組み」。`src/lib/` の session・flow・child-data・parent-data |
| Kotlin の窓口 | Android だけでできること（使用時間の取得・制限画面）を呼ぶための入口。中身はまだない |
