# 合流（手が空いた人が他の人を手伝う）

`npm run now` の「合流:」の行に、今の時間帯で何をしてよいかが出る。時刻は kit.config.json（milestones と help）。**時刻は未定・仮**。

## 決め方
- 合流は**同期点でだけ**決める（milestones の `sync: true`）。例外：`blocked` Issue が30分以上動かない時はまとめ役がその場で決めてよい。
- 決めるのはまとめ役（kit.config.json の facilitator）。手伝う人・手伝われる人の**両方に確認してから**。
- 決めたら `help` Issue を立てる（テンプレートあり）。手伝う人に assign。

## 期限
- 合流は **Issue を立てた後の最初の同期点まで**。`npm run now` に期限が出て、過ぎると「期限切れ」と出る。
- 期限が来たら、手伝った人は**自分の担当に戻る**のが基本。続けるなら同期点で決め直し、Issue を閉じて立て直す。
- 理由：終わりを決めないと、手伝いがずるずる続いて誰が何をしているか見えなくなるため。

## 時間帯ごとの手伝い方
| 時間帯 | してよい合流 | 例 |
|---|---|---|
| フリーズの `help.carveOutCutoffMinBeforeFreeze` 分前まで | 下の 1〜3 すべて | 処理を1つ切り出して新しいファイルで作る |
| そこからフリーズまで | **1 だけ**（新しいコードを増やさない） | 画面を操作して不具合を Issue にする、テスト、デモ用データ |
| フリーズ後 | 全員がデモの不具合修正・通し練習・録画 | — |

区切る理由：新しいコードは、main に入れて他の部分と繋ぎ、デモの流れで動くか確かめるまでに30分〜1時間かかる。フリーズ直前に入れると、繋ぎ目の事故がちょうど起きる。

## 手伝い方の種類（上から優先）
1. **コードを触らない手伝い**：テストを書く、デモ用データを作る、操作して不具合を Issue にする。衝突しない。
2. **切り出し**：手伝われる人のステップを1つ新しいファイルに切り出し、まとめ役が決め、lead が kit.config.json でそのファイルの所有者を手伝う人にする（PR）。範囲チェックはそのまま効く。手伝う人も着手宣言と preflight を通す。
3. **同じファイルを一緒に**：最後の手段。ペアで1つの画面を見ながら、書くのは片方だけ。
