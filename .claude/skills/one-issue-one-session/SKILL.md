# 1 Issue = 1 Session プロトコル

## 概要
本SKILLは、GitHub Issuesと連動した「1 Issue = 1 Session」開発体制において、AIエージェントが厳格に遵守すべき動作ルールおよびプロトコルを定義したものです。

---

## 1. 基本行動原則
1. **担当Scopeの遵守**:
   - あなたのタスクは指定された**1つのGitHub Issue（#X）の実装およびテストのみ**です。
   - コンテキスト汚染およびトークン消費を抑えるため、他Issueの領域や無関係なリファクタリングを勝手に行わないでください。
2. **スコープ膨張の禁止（例外処理の別Issue化）**:
   - 実装中に未考慮の境界条件、例外処理、あるいは追加機能のアイディア（「0のときの挙動」「別ログイン方式」等）を発見した場合、現在の作業コードに含めてはいけません。
   - 発見した例外事項は「別Issue候補（差し込みタスク）」として人間に報告し、メインIssueの実装をシンプルに完了させてください。

---

## 2. 開発・品質管理プロトコル
1. **テスト同梱基準の遵守**:
   - Issue内に定義されたテスト基準（単体テスト・動作検証手順）を満たすコードとテストコードをセットで出力してください。
2. **Linterおよび静的解析への適合**:
   - リポジトリで設定されているLinterおよびCI/CDチェック（構文エラー、フォーマット違反）に100%適合するコードを作成してください。

---

## 3. セッション終了・確認プロトコル（Closing Check）
人間（開発者）から以下のフレーズで問われた場合、必ずセッション終了前チェックを実行してください。

> **質問フレーズ**: 「このセッションを閉じて失われる情報はありませんか？」

### 必須自己診断チェック項目:
1. **未コミットファイルの有無**:
   - 作成・修正したコードやドキュメントで、コミット漏れになっているファイルはないか。
2. **チャット内合意事項の反映漏れ**:
   - セッション中のやり取りで決定した仕様変更や補足指定（例: 「UIカラーの調整」「ドキュメント記述」等）が、ファイルに正しく書き込まれているか。
3. **新規Issue切り出しの確認**:
   - 本セッション中に発覚した例外パターンや後回しにすべき事項が、報告漏れになっていないか。

チェック結果に問題がなければ、「失われる情報はありません。コミットおよびIssueのクローズが可能です。」と回答してください。

---

## 4. このリポジトリでの運用メモ
- 別 Issue 候補は、今の Issue に混ぜずにスキル `spawn-issue` の手順で下書きにし、人間の確認を取ってから `npm run issue` で立てる（AGENTS.md「絶対に守ること」）。
- 検査は `npm run check`、マージは `npm run merge`。詳細は AGENTS.md を見る。
