## 確かめた環境

- 調べた版: main の 9883d2b（PR #54 のセキュリティの修正を含む）。アプリのコードは変えていない
- サーバ: プロセスの中（PGlite・MOCK=1）と、127.0.0.1:3100 だけで待つテスト用サーバ（メモリの DB）。Neon・Vercel の Preview・本番にはつないでいない
- 仮想端末: AVD `SlopeVerify`（emulator-5556、Android 16 / API 36、RAM 2GB）。実機は使っていない
- アプリ: debug 版（SHA-256 `08d2a163…dece87`）と、確かめ専用の使い捨ての鍵で署名した release 版（SHA-256 `9c012806…353f67`。中身を見るだけで端末には入れていない。鍵は消した）
- アカウント: テスト用（mock）の保護者・子どもだけ。本物の Google アカウントは使っていない
- 計画の「1. 実装状況」は古い状態（Android アプリなし・API は health だけ）で書かれていたので、今の実装で確かめた

## いちばん大事な結果

**ほかの家族のデータを読む・変える・子どもの id を差し替える・役割を書き換える、はどれも断られた**（API-01〜08・10〜12、IPA-01・02）。
ログイン前・壊れた合言葉・ログアウト後の合言葉も断られ、SQL インジェクション・XSS・本文の大きさ・同じ送信の二重保存も守れていた。release 版にサーバの秘密・秘密鍵・DB の接続文字列はなく、release は自分たちの鍵で署名されていた。

## BLOCKED（7 件）

| ケース | 理由 |
|---|---|
| IN-10 | 計算のルールの一部（終了日を含むか・丸め方）が未決 |
| IPA-11（一部） | Android の Gradle にロックファイルがない（`android/` は生成物）。脆弱性の情報との照合はネットに出ないためしていない |
| IPA-15 | 監査の記録の表と「子どもを外す」画面がない。バックアップの復元は手元で試せない |
| PII-10（削除の機能） | 利用記録やアカウントを消す API がない |
| NET-02・NET-03 | 手元のサーバが http なので、CA 証明書を入れるプロキシの確かめは見送った。代わりに合言葉と QR の番号が logcat・保存・URL・通知に出ないことを確かめた |

## 判断を待つ所見（PASS にしたもの）

- 画面保護（FLAG_SECURE）がなく、最近使ったアプリの画面に保護者のグラフや子どもの QR が写る（AND-07・PII-06）
- 知らない道筋を開くと「Unmatched Route」画面が出て、URL と全部の道筋が見える（`+not-found.tsx` がない。AND-03）
- ホーム画面のウィジェットの受け口は、ほかのアプリから描き直しの合図を送れる（中身は変えられない。AND-02）
- 使っていなさそうな権限（`QUERY_ALL_PACKAGES`・外部ストレージ・`VIBRATE`）、開発用の scheme `exp+slope` が release に残る（AND-01・AND-10）
- QR を読んだだけの保護者に子どもの userId が返る（PII-03）

## もう1つの結果（result.md）との比べ

同じ計画を別に実行した [result.md](result.md)（76 件: PASS 52・FAIL 9・BLOCKED 11・N/A 4）と、主な結果は一致している。

- **両方で見つけた:** 合言葉の平文保存（PII-05）・外した子どもの前の記録が見える（PII-01 / PII-10）・NUL で 500（IN-06・IPA-12）・500 のログに入力がそのまま出て偽の行を作れる（IN-12）・ログインと QR の発行に回数の上限がない（AVL-01）・0001 年の日付を保存できる（IN-04）
- **result.md だけ:** X-1 空白期間だけの子どもで、設定を読むたびに `configVersion` が増える（安定性の不具合。`src/server/services/config-snapshot.ts:22`）・IPA-15 を FAIL（監査記録なし）としている
- **このまとめだけ:** AND-12 release の JS にデモの決まった合言葉が入る・PII-09 ログアウト後も出していた QR が使える・AND-11 端末の時計で上限をずらせる・空白だけの packageName で 500・health が DB 停止で 500

## 直すときの候補（私の見立て）

1. 入力の文字列から NUL などの制御文字を断る・空白だけを断る（Zod の契約で。5・6 がまとめて直る）
2. 500 のログに出す中身を絞る（4）
3. ログアウトで、出していた QR も無効にする（8）
4. デモのログインの部品を release 版に入れない（2）
5. 外した子どものデータを消すか、つないだ後の分だけ見せるかを決めて直す（1）
6. ログイン・QR を出す・利用記録の送信に回数の上限を足す（7）
