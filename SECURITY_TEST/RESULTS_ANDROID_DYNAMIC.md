### debug 版だから言えること・release では違いうること

- `android:debuggable=true` のため、`adb shell run-as com.quedotcom.androidslope` でアプリの中身（合言葉を含む）を PC から読めた（AND-05・IPA-13・PII-05 はこれで調べた）。release 版では run-as は使えない。ただし「平文で保存されている」こと自体は release でも同じ作り（AsyncStorage と SharedPreferences）のはず。
- `usesCleartextTraffic=true`（http を許す）。debug 版なので想定どおり。release 版の設定は確かめていない（NET-01 の担当）。
- dev client の部品が入っている: `expo-dev-launcher` の受け口（`expo-dev-launcher://` の AuthActivity、`exp+slope://`）、開発メニュー、LAN 上の開発サーバの一覧（立ち上げ直したあと、別の開発サーバ `10.3.17.201:8083` が候補に出た。押していない）。release には入らないはず（未確認）。
- 窓に `KEEP_SCREEN_ON` が付いている（開発用の部品が付けたと見られる）。
- 求める権限に `ACCESS_LOCAL_NETWORK`・`CHANGE_WIFI_MULTICAST_STATE` がある（開発サーバを探すための dev client 由来と見られる）。release で消えるかは未確認。
- 知らない道筋を開くと expo-router の既定の「Unmatched Route」画面が出て、開いた URL をそのまま表示し、「Sitemap」（全部の道筋と、開発モード・Metro の場所）へ行ける。`src/app/+not-found.tsx` がないので、release でも Unmatched Route は出る可能性がある（Sitemap が release でも出るかは未確認）。

### AND-02 Intent・受け手に、欠けた値・型違い・大きな値を渡す

- 判定: PASS
- 日時: 2026-10-18 15:00ごろ
- テスト用アカウント役割: ログインしていない状態
- 手順:
  1. `MainActivity` に data なしの VIEW、型違いの extra（`--ei role 999 --ez isParent true --es childId '../../x' --el userId -1 --efa token 1.5,2.5`）、端末の中で作った 100,000 文字の extra、8,000 文字の道筋の deep link を1回ずつ送った。
  2. 公開の receiver: ウィジェット `SlopeWidget` に `TODAY_UPDATED`（壊れた JSON の extra つき）と `APPWIDGET_UPDATE`（型違い）、`BootReceiver` に `BOOT_COMPLETED`、`DeviceOwnerBootReceiver` に `MY_PACKAGE_REPLACED` を送った。
  3. 非公開の部品: `StatusReportReceiver`（exported=false）への放送、`MonitorService`（exported=false）の起動。
  4. 毎回アプリのプロセス番号と画面を確かめた。
- 期待結果: 保護画面へ行かない・権限が変わらない・落ちない。
- 実結果:
  - MainActivity: どれも落ちず（プロセス番号が同じ）、ログイン画面のまま。
  - `APPWIDGET_UPDATE`・`BOOT_COMPLETED`・`MY_PACKAGE_REPLACED` は OS が `SecurityException`（Permission Denial）で止めた。
  - `MonitorService` は「not exported」で拒否。`StatusReportReceiver` は放送が「完了」と出たが、受け手は action が `ACTION_HEARTBEAT` でなければ何もしない作り（`StatusReporter.kt`）。
  - `TODAY_UPDATED` だけは外から届いた（公開ウィジェットのカスタム action に権限がない）。ただし受け手は extra を読まず、自分の保存した値で描き直すだけ（`SlopeWidget.kt`）。
  - `DeviceOwnerReleaseReceiver`（`android.permission.DUMP` で保護。adb の shell は DUMP を持つ）は、送ると本当に解除の処理が走るので送っていない。静的に保護の権限だけ確かめた。
- HTTP status / 相関ID: なし（端末内だけ）
- 証拠: 作業中の画面確認のみ（画面はログイン画面のまま）。logcat の `Permission Denial` の行
- 影響と再現頻度: 毎回同じ。所見（低）: どのアプリからでもウィジェットの描き直しを何度でも起こせる（中身は変えられない）。

### AND-05 バックアップの設定と、平文で保存されているもの

- 判定: PASS（バックアップ）。平文の保存は PII-05 で FAIL として記録
- 日時: 2026-10-18 14:55〜15:00、15:25、15:37
- テスト用アカウント役割: ログイン前・保護者・子ども
- 手順: 端末の APK を取り出し `aapt2 dump xmltree` で Manifest を見た。`dumpsys package` のフラグを見た。`run-as`（debug 版だから使える）でアプリの領域のファイル名・キー名・値の長さ・JSON の項目名だけを出した（値は出していない）。
- 期待結果: 秘密をバックアップへ入れない。機微データを適切に守る。

  - `android:allowBackup=false`、`android:dataExtractionRules` で cloud-backup と device-transfer の両方から全部の置き場（root・file・database・sharedpref・external・device_*）を外している。`dumpsys` のフラグにも ALLOW_BACKUP がない。
  - アプリの領域（`/data/data/…`）は `drwx------`。shell から直接は読めない。外部ストレージ（`/sdcard/Android/data/…`）には何もない。
  - 平文で入っているもの（種類だけ）: 保護者・子どもの合言葉と userId・名前・役割（`slope.session`）、子どもの設定のキャッシュ（約 8.6KB）、前に送ったアプリの一覧、送信待ち。Kotlin 側 `slope_engine.xml` に子どもの合言葉（`report_token`）・childId・送り先・今日の使用量・制限の値。ウィジェット用 `slope.widget.xml` にテストの日程と（保護者のとき）子どもの日ごとの値。
- 証拠: 本文（キー名・長さの一覧は作業中に出したもの。値は記録していない）
- 影響と再現頻度: debug 版では run-as で誰でも読める（release では使えない）。
